Here's how JACE currently receives settlements from BondAI:

Step 1: BondAI creates a settlement session
BondAI sends a request to JACE at POST /api/external/settlement/session with the trade details — trade ID, amount, bond name, investor email, etc. BondAI authenticates this request using a shared secret sent in the header. JACE creates a database record for the session and sends back a signed token along with a URL like /settlement?session=<token>.

Step 2: Investor interacts via iframe
BondAI opens that URL inside an iframe on their platform. The investor sees the settlement details (bond name, amount, trade info) and enters a payment reference number. When they submit, JACE marks the session as "submitted" — but nothing else happens yet. No notification goes back to BondAI at this point.

Step 3: JACE admin manually confirms
A JACE team member (admin, accounting, ops, or investor relations role) goes to the internal /settlements inbox page. They review the submitted settlement and either:

Confirm it — which marks it as "settled," generates a PDF receipt, and then sends a webhook notification back to BondAI saying the settlement is complete.
Cancel it — which marks it as "cancelled" with a reason.
In short: BondAI pushes settlement requests into JACE via that session-creation API call. The investor submits their payment info through an embedded iframe. Then a JACE team member manually verifies and confirms (or rejects) the settlement before BondAI gets notified of the outcome.
